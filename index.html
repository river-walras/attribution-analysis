归因分析：原理与实盘做法

TL;DR —— 归因分析回答「组合今天赚的钱，有多少来自风格因子，多少来自行业，多少是我主动选股带来的」。核心思路：先用每日截面 OLS 算出各因子当天的「收益率」，再乘以组合对该因子的暴露，就得到组合从该因子获得的收益；剩下无法解释的部分就是特异收益。

① 整体流程一览

  1. 1
    截面 OLS —— 每个交易日，用全市场股票当天的因子暴露（X）和次日收益率（Y）做横截面回归，得到各因子的「收益率」（beta）。由平台 API get_factor_style_returns() 完成。
  2. 2
    计算组合暴露 —— 用组合持仓权重加权平均个股因子值，得到组合在每个因子上的整体暴露。T 日收盘后计算，对应 T+1 日的收益。
  3. 3
    归因分解 —— 组合因子收益 = 组合暴露（T 日）× 因子收益率（T+1 日）；特异收益 = 总收益 − 所有因子收益之和。

② 截面 OLS：算出因子收益率

这是整个归因体系的基础。每个交易日，在全市场做一次横截面回归，把个股次日收益率「解释」成各风格因子的线性组合。

OLS 变量说明

X（解释变量）  每只股票在该日的因子暴露矩阵。行 = 股票，列 = 各风格/行业因子（已标准化）。

Y（被解释变量）  每只股票在次日（T+1）的收益率向量。

β（回归系数 / beta）  各因子的「收益率」，即因子在该日多赚（或亏）了多少。这就是 factor_returns。

残差 ε  每只股票无法被因子解释的部分，即个股的选股 alpha。

      X 的维度

      行 = 全市场 N 只股票（通常几千只）
      列 = 因子数量（风格 16 个 + 行业 30+ 个 + country 1 个）

      Y 的维度

      长度为 N 的列向量，即每只股票 T+1 日的实际收益率（次日涨跌幅）

      β 的含义

      每个因子在这一天的「收益贡献率」。例如 size 的 β = 0.2%，表示 size 因子这天贡献了 0.2% 的收益

      残差的含义

      个股被因子解释不了的那部分收益。聚合到组合层面就是组合的「特异收益」

      实盘注意 这一步的 OLS 并非在 AttributionAnalysis 类里手动实现，而是通过平台 API get_factor_style_returns() 获得已算好的 factor_returns（每日每因子的收益率 DataFrame）。平台内部使用的是加权最小二乘（WLS），以市值平方根为权重，使大市值股票有更高影响力。

      ③ 计算组合的因子暴露

      暴露回答「我的组合在哪些因子上押注了多少」。计算方法非常直接：持仓加权平均。

        country 暴露

        country 暴露比较特殊，不是因子值加权，而是直接等于总持仓比例（所有股票权重之和）。如果仓位 80%，则 country 暴露 = 0.8，剩余 20% 视为现金。

              ⑦ 注意事项 & 常见误区

              T 日暴露 vs T+1 日收益 —— 一定要用 T 日收盘后计算的暴露来解释 T+1 日的收益。代码里用 .shift(1) 实现。如果不 shift，相当于用未来暴露解释当日收益，逻辑错误。
              因子收益率不是你自己算的 —— factor_returns 通过 get_factor_style_returns() 从平台获取，内部是全市场截面 WLS 的结果（以市值加权）。你的组合规模再大，也不会影响这个数字。
              特异收益 ≠ 选股能力 —— specific_return 是「模型无法解释的残差」。如果你的组合里有因子模型覆盖不全的行业或小市值股票，这部分也会被归入特异收益。只有在因子覆盖充分的前提下，特异收益才接近真实选股能力。
              累积收益的加总有复利误差 —— 日收益直接加总会低估（多头）或高估（空头）真实累积收益。代码用 \(\text{attr}_k(t) \times \text{NAV}(t-1)\) 再累加的方式近似复利修正。如需精确，应按净值曲线反推。
              仓位不满时的 country 收益 —— country 因子代表「持有股票」本身带来的系统性收益（市场 β）。如果相对基准仓位低 20%，这 20% 的现金相当于空了指数，在牛市里会拖累超额收益，体现为 cash 为负。

              附录：因子预处理（preprocess.py）

              归因分析使用的因子暴露矩阵 X 并不是原始财务数据，而是经过一套标准化流程处理后的值。preprocess.py 提供的四个函数，正是这套流程在本库中的实现，供你在把自有因子传入归因体系之前使用。

              在哪里用？ 如果你有自己计算的原始因子（如自定义的动量、质量因子），在传给 AttributionAnalysis 或做截面 OLS 之前，应该先走完这套预处理流程，否则量纲不统一、异常值会严重扭曲回归结果。对于 JQData 平台内置的 Barra 风格因子，平台已在内部完成这些步骤，无需重复处理。

              ① 去极值：消除异常值干扰

              原始因子值往往有少数极端值（如市净率极高的壳公司），会严重拉偏截面回归。去极值把这些值截断到合理范围，不是删除，而是压缩到边界。

              sigma 法 — winsorize(data, scale=3)

              计算截面均值 μ 和标准差 σ，将超出 [μ − 3σ, μ + 3σ] 的值截断到边界。适合分布接近正态的因子。

              MAD 法 — winsorize_med(data, scale=3)

              以中位数和绝对中位差 MAD 为基准，截断范围为 [median − 3×MAD, median + 3×MAD]。对偏态分布、含大量小票的截面更稳健。

                ② 中性化：剥离行业和市值的混淆效应

                风格因子（如动量、质量）往往和行业、市值高度相关。若不剥离，OLS 回归出的 beta 并不能干净地代表「风格因子本身的收益」，而是混入了行业或市值的影响。中性化就是把这部分影响回归掉，只保留残差。

                  # 对行业（申万一级）和对数市值做中性化
factor_neutralized = neutralize(
    factor_raw,
    how=['sw_l1', 'ln_mktcap'],
    date='2024-01-02'
)
# 返回值是 OLS 残差，即剔除行业和市值影响后的纯因子值

                  ③ 标准化：统一量纲

                  不同因子的量纲完全不同（PE 是倍数，换手率是百分比，市值是亿元），直接放进同一个 OLS 会使 beta 的大小没有可比性。截面 z-score 把每个因子当天的分布统一为均值 0、标准差 1，使各因子的 beta 可以直接比较大小。

                  顺序不能乱 —— 必须先去极值再中性化再标准化。若先标准化再去极值，极端值已被压缩进 z-score，去极值效果大打折扣；若先中性化再去极值，残差里的异常值会污染中性化结果。
                  行业因子不走这套流程 —— 行业因子是 0/1 虚拟变量（one-hot），本身已无量纲，不需要去极值或标准化。country 因子同理，直接用总仓位比例。

                  环节处理方式代码位置
                  持仓权重为 0 替换为 NaN，计算暴露时通过 dropna() 排除，不参与加权平均 attribution.py:120
                  风格因子值缺失 sum(axis=1, min_count=1)：至少有一个有效值才返回结果，全部缺失才输出 NaN attribution.py:185
                  行业暴露缺失 reindex(..., fill_value=0)：当天未持有的行业暴露补 0（不持有即零暴露，语义正确） attribution.py:219
                  缓存文件不存在 返回全 NaN 的空 DataFrame，保持索引结构不破坏后续计算，同时触发日志警告 factor_cache.py:231
                  中性化后残差为 NaN 可选 fillna 参数，用该股票所属行业的残差均值填充（适合数据覆盖不全的小票） preprocess.py:293
                  截面 WLS 中因子值缺失 该股票从当日回归样本里直接剔除，不参与 beta 估计。全市场仍有几千只股票，影响可忽略 平台内部
                  neutralize 中的 OLS 缺失 先用 np.isfinite 过滤有效索引，再传入 missing='drop' 双重保险，缺失观测完全剔除 preprocess.py:279–289
                  缺失值不等于零暴露 —— 风格因子暴露为 NaN 时，该股票不参与加权（分子分母都不计入），等价于把它从组合里剔除再算平均。如果改成填 0，会错误地把缺失数据当成「该因子暴露为零」，拉低组合暴露估计值。
                  缺失数据会虚增特异收益 —— 某只股票当天因子值缺失时，它的暴露贡献为零，但它的实际收益仍然计入组合总收益。这部分收益无法被任何因子解释，全部落入 specific_return。因此，持有大量小票（数据覆盖差）的组合，特异收益会系统性偏高，不能直接等同于选股 alpha。

                  Universe 选取

                  截面 OLS 的样本范围（universe）决定了「用哪些股票来估计因子收益率」。代码里 get_factor_style_returns 硬编码了 universe='zzqz'（中证全指），即沪深两市全部 A 股。

                  Universe样本规模适用场景风险
                  zzqz 中证全指约 4000+ 只全市场通用，因子收益率估计最稳定推荐
                  hs300 沪深300300 只大盘组合size 因子收益率失真，小盘归因偏差大
                  zz500 中证500500 只中盘组合缺少极端小盘，size 溢价被低估

                  HS300 Universe 的两个具体问题

                  问题一：beta 估计不稳定

                  HS300 全是大市值，size 值挤在高端，截面方差很小。分母变小导致 beta 数值放大且对噪声更敏感——同样的 Cov，分母缩小一倍，beta 就翻倍，但这个 beta 不代表真实溢价，只是数值偶然变大了。

                  问题二：beta 含义失真

                  HS300 估出的 size 因子收益率描述的是「大盘内部，相对大一点 vs 相对小一点的收益差」，而不是「大盘 vs 小盘的真实溢价」。用这个 beta 归因小盘组合，就像用北京天气预报预测上海气温。

                  对小盘组合的实际影响

                  归因等式是：

                  当 universe 选错时，两边都会出问题：

                  zzqz（正确）HS300（错误）
                  size 因子收益率 捕捉到真实的小盘溢价，含义明确 只反映大盘内部差异，与小盘溢价无关
                  size 贡献归因 准确反映组合的 size 下注收益 size 贡献被严重低估或方向错误
                  specific_return 真实的选股 alpha 虚高——size 没解释到的部分全堆进来了
                  一个直觉例子 —— 假设某天小盘股整体涨了 3%，大盘股涨了 1%。你持有小盘组合，size 暴露为 −0.8（相对基准）。

                  用 zzqz 估出的 size 因子收益率能捕捉到这 2% 的大小盘价差，归因结果：size 贡献 ≈ −0.8 × (−2%) = +1.6%（做空大盘获益）。

                  用 HS300 估出的 size 因子收益率只看大盘内部差异，可能只有 0.1%，归因结果：size 贡献 ≈ −0.8 × (−0.1%) = +0.08%，剩下的 1.5% 全跑到 specific_return 里，让选股能力看起来虚高。
                  这是已知局限，没有通用解法 —— 理论上应该用「与组合最接近的 universe」来估计因子收益率，但实际上很难界定边界，且会引入另一种选择性偏差。工程上的折中是始终用 zzqz，并在解读 specific_return 时结合组合的市值分布一起判断。

                  行业分类标准

                  初始化 AttributionAnalysis 时的 industry 参数决定了行业因子的粒度。

                  sw_l1 — 申万一级行业（默认）

                  31 个行业，覆盖最广，行业划分与主流研究报告一致，适合大多数组合。行业归因结果可读性强。

                  jq_l1 — 聚宽一级行业

                  19 个行业，粒度更粗。行业数少意味着行业虚拟变量矩阵更小，截面 OLS 自由度略高，但行业归因细节会被合并。

                  行业分类会跨期变化 —— 股票的行业归属不是固定的（如重组、主业转移），代码在初始化时取分析期首尾两日的行业列表取并集（attribution.py:126），确保新老行业代码都被覆盖，不会因为行业调整导致某天暴露为 NaN。

                  权重归一化

                  当某日持仓权重之和超过 1（如杠杆或数据误差），代码自动归一化，同时影响 country 暴露的计算：

                  # attribution.py:119-120
weights.loc[weights.sum(axis=1) > 1] = weights.div(weights.sum(axis=1), axis=0)
# 归一化后权重之和 = 1，country 暴露 = 1，视为满仓，不产生现金项
                  权重之和country 暴露归因中的现金项
                  = 1（满仓）1.00（无现金拖累）
                  < 1（部分仓位）< 1，等于实际仓位比例非零，牛市为负（持现金跑输指数）
                  > 1（自动归一化后）归一化至 1.00

                  WLS vs OLS

                  平台内部的截面回归实际上是加权最小二乘（WLS），而非等权 OLS，权重为每只股票总市值的平方根：

                    为什么用市值加权？ —— 等权 OLS 会让数量众多的小市值股票主导回归结果，而小票的收益噪声更大、因子值质量更差。用 √市值 加权后，大市值股票对 beta 估计的贡献更大，因子收益率更能反映「可投资」市场的真实情况，也更符合实盘中以市值衡量的经济重要性。

                    本地缓存机制

                    第一次运行归因分析时，代码会从平台拉取因子数据并写入本地缓存，后续只增量补充缺失日期，大幅减少 API 调用。

                    缓存目录 —— 默认存放在 ~/jqfactor_datacache/bundle/，可通过 set_cache_dir(path) 修改。

                    目录结构按因子组和月份组织，每天一个 Feather 文件：

                    ~/jqfactor_datacache/bundle/
└── jqfactor_cache_<md5>/        # 因子组（由因子名列表的 MD5 确定）
    ├── 202401/
    │   ├── 20240102.feather      # 每个交易日一个文件
    │   ├── 20240103.feather      # 行 = 股票代码，列 = 各因子值
    │   └── ...
    └── 202402/
        └── ...
                    机制说明
                    格式Apache Feather（列式存储），读取速度远快于 CSV，支持 NaN
                    因子组识别用因子名列表排序后的 MD5 哈希命名文件夹，同一组因子共用缓存，顺序无关
